# 田智 · 运行说明

> 河北农业大学首届大学生人工智能素养大赛 · A 赛道「AI 智构」交互智能体创意
> 作品名称：**田智 —— 华北平原农事决策助手**

---

## 一、这是什么

一个面向华北平原种植户的**农事决策网页应用**。输入地块位置和作物，它回答三件事：

1. **未来 7 天，哪天几点适合打药？**
2. **这几天要不要浇水？**
3. **今天和未来一周天气如何、有什么农事风险？**

核心不是"聊天"，而是**把天气数据翻译成可执行的决定**：不说"明天东南风 3 级"，而说"明天 10 点到 13 点适合打药，风速 0.9 m/s"。

## 三、如何运行

### 方式零：直接访问在线版（最推荐，手机电脑都行）

浏览器打开：

```
https://leeforword.github.io/zhishi-zhinong/
```

纯静态页面，没有任何后端。手机上还能**安装到桌面**，成为一个独立图标、
全屏运行、断网也能打开界面（天气数据仍需联网）。
安装与部署的完整步骤见 [部署与安装.md](部署与安装.md)。

> HTTPS 有两件事只有它能做：安装 App、以及浏览器定位 API。
> 在线版两者都有，这也是它比本地双击打开更完整的原因。

### 方式一：start.bat（本地开发用，功能最全）

双击项目根目录的 **`start.bat`**，浏览器会自动打开 `http://127.0.0.1:8931`。

**只有这种方式下「用我的位置」才能用** —— 浏览器规定定位 API 只能在 `https` 或 `localhost` 下工作。

手动启动等价于：

```bash
cd web
node server.mjs 8931
```

### 方式二：直接双击 index.html

也能正常使用（天气、地图、图表都正常），**区别是「用我的位置」不可用**，因为 `file://` 不是安全上下文；
Service Worker 也不会注册，因此没有离线能力。

## 四、界面与功能

### 左侧：地块管理

- 预置 4 块示例地块（保定、石家庄、邯郸、衡水）
- **点击地块** → 右侧全部数据切换
- 悬停/选中时出现 **✎ 编辑** 和 **× 删除**（触屏设备按钮常显）
- **删除采用行内确认**，不弹系统对话框，且可先取消
- 数据保存在浏览器 localStorage，**刷新不丢失**

### 新增/编辑地块

点「＋ 新增地块」打开弹窗，地点有三种选法：

1. **搜地名** —— 输入县市名，本地字典 126 个华北县市优先，找不到自动在线检索
2. **点预设** —— 保定、石家庄、邯郸、邢台、衡水、沧州、廊坊、唐山、北京、天津、德州、安阳
3. **地图点选** —— 展开河北地图（高德 JS API 官方底图 + 河北行政边界叠加），点任意位置自动反查"这是哪个县"，显示如「河间市（沧州市）」
   - 可切换 **路网 / 卫星** 图层
   - 坐标做了 GCJ-02 → WGS-84 转换（两者差约 500 米，不转会导致县界附近判断错县）

> 地名一律以坐标所在行政区为准，不会出现"名字和坐标对不上"的情况。

### 中间：决策区

- **最佳作业窗口**：精确到小时
- **多模式一致性**：同时比对欧洲 ECMWF、美国 GFS、德国 ICON、中国 CMA 四个气象模式，如实提示是否存在分歧
- **未来七天**：每天打药可行性，**点某一天，下方图表切换为该日**
- **今天的建议**：打药 / 灌溉 / 晾晒，每条写明判断依据
- **数据分析**：五张图表（下方详述）
- **问一句**：自然语言问答

### 多气象模式一致性检查（重要的诚实性设计）

不同数值预报模式对同一地点的结论可能明显不同。实测同一地块：

| 模式 | 未来 7 天可作业天数 |
|---|---|
| 欧洲 ECMWF | 3 天 |
| 德国 ICON | 1 天 |
| 中国 CMA | 1 天 |
| 美国 GFS | **无窗口** |

本作品的做法不是取平均、也不是赌某个模式最准，而是**把分歧如实告诉用户**：

- 模式全部认为有窗口 → 「结论一致」
- 模式之间有冲突 → 「⚠ 气象模式之间存在分歧」并列出各模式的天数，建议临近日期再确认

这样当评委追问"你这天气预报准不准"时，答案是有依据的：**我们不假装单点预报绝对可靠，而是主动暴露不确定性**。

### 数据分析图表

| 图表 | 说明 |
|---|---|
| 逐小时风速曲线 | 虚线是 2.5 m/s 作业上限，绿色底色为可作业时段，超阈值点标红 |
| 作业窗口热力图 | 7 天 × 24 小时，一格一小时，标出可作业 / 风大 / 气温低 / 气温高 / **降雨拦截** |
| 温度与降水 | 最高温、最低温双曲线 + 逐日降水柱（独立区域） |
| 一周可行性环形图 | 可作业 / 需谨慎 / 不宜 的天数分布 + 关键数字 |
| 长势趋势 | 多时相长势指数，**明确标注为示意数据** |

所有图表为手写 SVG，未使用任何图表库。

## 五、大模型是怎么用的（重点）

这是本作品的**核心设计原则**：

> **大模型不参与任何数值计算。所有数字来自规则引擎对真实天气数据的计算。**

大模型只做三件事：

| 用途 | 说明 |
|---|---|
| **意图识别** | 用户说"啥时候能喷"，规则匹配不到 → 模型判断属于"打药时机" → 仍由规则引擎产出答案 |
| **话术改写** | 把结构化结论说得更像农户口语 |
| **超范围兜底** | 不属于能力范围时礼貌说明，不硬答 |

### 数字一致性校验（安全机制）

模型改写完的结果要过一道检查：**输出里每个数字都必须在原始答案中出现过**，否则直接丢弃、回退到模板。

允许的唯一例外是时间制式转换（`14:00` → "下午2点"），因为这语义完全等价。

实测效果：模型若自行添加任何新数字（如编造"7 天"），会被立即拦截并使用原答案。

### 如何切换

问答卡片右上角有 **AI 增强 开/关** 按钮：

- **开**：意图识别 + 口语化改写（默认）
- **关**：纯规则引擎模式，回答为固定模板

答辩时可现场对比两种模式，证明"数字不依赖模型"。

### 配置位置

`web/config.js`（会提交到公开仓库，只放可以公开的 key）：

```js
window.TIANZHI_CONFIG = {
  deepseekKey: '',                 // 公开版留空，AI 自动退回纯规则引擎
  deepseekModel: 'deepseek-chat',
  enableLLM: false,                // 公网版无 key，默认关闭

  amapKey: '...',                  // 高德地图 Web端 key（建议绑域名白名单）
  amapSecurityJsCode: '...',       // 高德安全密钥

  qweatherKey: '...',              // 和风天气（免费额度）
  qweatherHost: '...',             // 账号专属 API Host
  enableQWeather: true,

  enableMultiModel: true,          // 多气象模式一致性检查开关
  timeoutMs: 9000
};
```

本地想打开 AI 润色，新建 **`web/config.local.js`**（已被 `.gitignore` 忽略，不会上传）：

```js
Object.assign(window.TIANZHI_CONFIG, {
  deepseekKey: '你的 key',
  enableLLM: true
});
```

页面会在 `config.js` 之后加载它；`scripts/build-site.mjs` 构建公网版时会跳过这个文件。

> ⚠️ **安全提示**：高德与和风是浏览器端直接调用，key 会随页面源码暴露，
> 所以高德必须去控制台绑定域名白名单，和风要接受"额度可能被刷满、随时可换"这个前提。
> DeepSeek 按量计费，**不入库**。
>
> 注：高德 key 是「Web端」类型，只能用于 JS API，**不能调用 REST 接口**（会返回 `USERKEY_PLAT_NOMATCH`）。这是正常的平台限制。

## 六、数据来源

| 内容 | 来源 | 说明 |
|---|---|---|
| 实时天气 | [Open-Meteo](https://open-meteo.com) | 逐小时 168 小时 + 逐日 7 天预报，免费、无需 key |
| 天气模式 | ECMWF / GFS / ICON / CMA | 四个全球数值预报模式，用于一致性比对 |
| 地图底图 | **高德地图 JS API**（官方授权调用） | 路网图 + 卫星图可切换，含审图号 |
| 行政区划边界 | 阿里 DataV GeoAtlas | 河北省 + 11 地级市 + **167 个县级单元**，离线内置（155 KB），叠加到高德底图上 |
| 点位反查县名 | 本地 GeoJSON 点面判断 | 离线、免费、准确，不依赖在线服务 |

### 关于坐标系

高德地图用 **GCJ-02**（火星坐标），天气数据和行政区划数据用 **WGS-84**，两者在华北地区相差约 **500 米**（实测保定 557m、河间 516m、石家庄 543m）。

本作品做了双向转换：
- 点击地图 → 高德给 GCJ-02 → **转成 WGS-84** → 再与县界比对（否则县界附近会判断错县）
- 显示标记 → 把 WGS-84 存储的坐标 **转成 GCJ-02** → 画到高德地图上

## 九、已知限制（如实说明）

| 限制 | 说明 |
|---|---|
| 农事阈值为公开常识 | 风速 2.5 m/s、气温 5–32℃ 等阈值**未经当地农技部门核定**，界面已标注"待核实" |
| **天气预报本身有不确定性** | 不同模式结论可能相反（实测 GFS 说无窗口、ECMWF 说 3 天可作业）。作品已做一致性提示，但这仍是农业 AI 的根本难点 |
| 天气网格约 9–11 km | 代表县域范围，不是单个地块；请求坐标会被吸附到最近网格点（偏移 1–5 km） |
| 长势趋势为示意数据 | 真实遥感未接入，曲线仅演示形态，界面已明确标注 |
| 无作物生育期模型 | 目前只区分冬小麦/夏玉米，没有越冬期、拔节期等阶段差异 |
| 打药未考虑风向与药后降雨 | 目前只看风速与当日降水，农学上还应判断喷后 6–24 小时降雨 |
| 病虫害识别、测土施肥未做 | 属于后续版本，问答中会明确拒答而不编造 |
| 地图高德 key 为 Web端类型 | 只能调 JS API，不能调 REST 接口；行政区查询（DistrictSearch）服务未开通，边界改用本地 GeoJSON 绘制 |
| 地图最大缩放 | 高德缩放级别 6–16，能看清县界与主要道路，但看不出单块田的边界 |
