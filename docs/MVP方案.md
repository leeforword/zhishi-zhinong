## 1. 一句话目标

**输入地块位置和作物，系统每天自动回答：未来 7 天哪天下地干活最合适、哪天有灾害风险、这块地的长势在变好还是变差。**

---

## 2. 已确认的方向（决策记录）

| 维度 | 结论 | 说明 |
|---|---|---|
| 用户 | 种植户 / 合作社 | 田间一线，需要的是"我现在该干什么"，不是"这是什么" |
| 区域 | 华北平原（河北/山东/河南等） | 冬小麦—夏玉米一年两作 |
| 作物 | **冬小麦 + 夏玉米**（首版） | 其余作物留配置位，不实现 |
| 界面 | **电脑大屏网页为主**，手机 H5 自适应可用 | 一套功能，响应式布局；不单独做移动端特化 |
| 节奏 | 1-2 周 MVP | 先验证核心链路 |
| 数据 | 从零起步 | 用公开天气接口 + 示例地块遥感，不采购数据 |
| 范围 | **只做天气/遥感预警决策** | 架构预留扩展，见第 8 节 |

### 为什么首版收窄到小麦 + 玉米

- 选中的 5 类作物中，水稻在华北平原只有零星分布，不是主力；大豆油菜、果树经济作物的规则集与禾谷类差异大，写入会增加约 2 倍工作量；
- 小麦和玉米是华北一年两作的核心，**天气阈值相近、灾害类型同源**（倒春寒、干热风、连阴雨、干旱、涝渍，两茬都能共用一套规则引擎）；
- 2 周是硬约束，2 个作物的规则库是可完成的，5 个不是。

### 为什么"天气/遥感预警"适合做第一场景

1. **不需要标注数据**——天气有免费公开接口，遥感有公开数据源，规则先用农学阈值手写，不训练模型；
2. **反馈周期短**——今天说"后天有连阴雨，打药提前"，用户马上能判断对错；
3. **是执行指令而不是知识问答**——直接回答"什么时候干什么"，这是种植户真正的痛点。

## 3. 用户要做的四件事（MVP 验收线）

### 3.1 建立地块
- 地图上点选或画多边形圈出地块，或者输入县/村名 + 面积；
- 选择作物（冬小麦 / 夏玉米）和播期；
- 保存为"我的地块"。

### 3.2 天气农事窗口
把天气数据翻译成**"这类农活哪天能干"**：

| 农事 | 制约条件（示例，最终以农技依据为准） |
|---|---|
| 喷药/施药 | 24h 内无雨、风速低于阈值、温度在区间内 |
| 追肥 | 有降雨配合、避免大暴雨冲刷 |
| 灌溉 | 持续无有效降水 + 高温/大风 |
| 收获/晾晒 | 连续晴好、无降雨风险 |
| 播种 | 土壤墒情 + 播期 + 出苗温度 |

输出形态：未来 7 天日历，每天标记 ✅可干 / ⚠️谨慎 / ❌不宜，并写明**原因一句话**。

### 3.3 遥感长势判读
- 取该地块 Sentinel-2 的 NDVI/NDMI 时间序列；
- **输出用大白话，不出现指数原值**：
  - "这块地比周边同类地块长势偏差，且近 2 周在变差"；
  - "墒情指标偏低，结合未来无雨，建议关注灌溉"；
- 每条结论附**依据**（数据来源 + 对比方式 + 日期范围）。

### 3.4 自然语言问答（限定作用域）
- 示例问题："我这几亩小麦现在要不要追肥？""下周能打药吗？"
- **关键约束：不让模型自由编数字。** 数字一律来自规则引擎和真实数据源，LLM 只负责把结构化结论转成人话、解释原因。
- 问题超出首版作用域（如问病虫害识别）时，明确回答"这个方向还没做"，不硬答。

## 4. 技术架构

```
┌─────────────────────────────────────────────┐
│  前端（响应式，桌面优先）                      │
│  地图/地块 · 遥感图层 · 天气时间轴 · 决策卡片  │
└────────────────────┬────────────────────────┘
                     │ REST / JSON
┌────────────────────▼────────────────────────┐
│  后端                                        │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
│  │ 数据源适配│ │ 规则引擎  │ │ 问答(LLM)    │ │
│  │   层     │ │          │ │ 只做转述      │ │
│  └────┬─────┘ └────┬─────┘ └──────────────┘ │
│       │            │                         │
│  ┌────▼────────────▼──────────────────────┐  │
│  │ 规则库（作物参数 + 农事阈值，配置化）    │  │
│  └────────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
         │                    │
   ┌─────▼─────┐      ┌───────▼────────┐
   │ 天气 API   │      │ 遥感数据源      │
   │ Open-Meteo│      │ Sentinel-2     │
   │ /和风天气  │      │ (示例地块先手导)│
   └───────────┘      └────────────────┘
```

### 4.1 关键设计：数据源适配层
天气、遥感各自封装成统一接口 `DataSource.get(params) -> 标准化结果`。日后加土壤传感器、气象站、第三方遥感平台时，**只加适配器，不动上层**。

### 4.2 关键设计：规则库配置化
每条规则写成结构化配置，例如：

```yaml
rule_id: spray_window
crop: [wheat, maize]
stage: all
conditions:
  - {field: rain_24h,   op: "<", value: 2,  unit: mm,  reason: "24小时内有降雨，药效会被冲掉"}
  - {field: wind_speed, op: "<", value: 3,  unit: m/s, reason: "风力偏大，飘移风险"}
  - {field: temp_avg,   op: "in", value: [5, 32], unit: °C, reason: "温度不在适宜区间"}
source: "农技依据来源待标注"
```

**每条规则必须带 `source` 字段**（阈值来自哪里），这是后续可审计、可纠错的前提。

### 4.3 技术选型建议（不锁定）
- 后端：Python + FastAPI（农学规则和数据处理生态好）；
- 前端：React + 地图库（若团队更熟 Vue 也可替换）；
- 存储：MVP 阶段用 SQLite 即可，不必上数据库服务；
- LLM：只用于问答转述和解释，不参与数值计算。

## 5. 两周排期

| 时间 | 交付 |
|---|---|
| 第 1-2 天 | 项目骨架、天气接口接入跑通、地块 CRUD |
| 第 3-4 天 | 规则引擎框架 + 喷药/灌溉/收获窗口规则（小麦玉米各一套） |
| 第 5-6 天 | 前端：地图选地块 + 7 天天气日历 + 决策卡片 |
| 第 7 天 | **中期自查**：拿一个真实地块跑一遍，结果是否说得通 |
| 第 8-9 天 | 遥感接入（先用手导的示例地块数据，不求自动化） |
| 第 10 天 | NDVI/NDMI 转大白话判读逻辑 |
| 第 11 天 | 问答入口 + LLM 转述层 |
| 第 12 天 | 响应式适配（手机可用） |
| 第 13-14 天 | 端到端联调、找 1-2 个真实种植户试用反馈、修问题 |

**中期自查是硬关卡**：第 7 天如果决策结果本身说不通，先修规则，不要往后堆功能。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **数据从零起，遥感接入比预期慢** | 演示不完整 | 遥感降级为"手导示例地块"，**不阻塞 MVP 主体**；天气接口第一天就要跑通 |
| **农学阈值写错，给出错误建议** | 用户实际损失 | 每条规则标注依据来源；界面固定免责声明；首版只做"提示"不做"命令" |
| **用户看不懂指数** | 产品不可用 | 所有输出强制翻译成"打不打药/灌不灌水/哪天干"，术语默认隐藏 |
| **作物选得太宽** | 2 周做不完 | 已收窄到小麦 + 玉米 |
| **LLM 幻觉编造数字** | 可信度崩塌 | LLM 只做转述，数值全部来自规则引擎；问答超范围明确拒答 |
| **多云导致遥感数据缺失** | 序列断层 | 选数据时容忍缺测，明确标注"近期无有效影像"，不做插值编造 |

## 7. 界面布局

### 桌面端（主界面）
```
┌──────────────┬────────────────────────┬──────────────┐
│  地块列表     │       地图 / 遥感图层     │  今日决策卡片  │
│              │                          │  ───────────  │
│  · 东洼地10亩 │      （选中地块高亮）      │  ✅ 今天可打药 │
│  · 南坡6亩    │                          │  ⚠️ 3天后有雨  │
│  · 北地块15亩 │                          │  📉 长势偏差   │
│              │                          │  ───────────  │
│  [+ 新建地块] │                          │  7 天天气时间轴 │
└──────────────┴────────────────────────┴──────────────┘
```

### 移动端（自适应收窄）
同一套功能，单列堆叠，**首屏只放"今天到后天的提醒"和"地块长势"**，地图和时间轴折叠到二级页面。

## 8. 为后续扩展预留的结构（现在不实现）

| 预留点 | 怎么做 | 目的 |
|---|---|---|
| 作物参数 | 作物类型/品种/播期做成**配置表**，不写死在代码里 | 日后加水稻、大豆只需加配置 |
| 决策规则 | 规则库独立模块，规则是数据不是代码 | 日后加测土施肥、病虫害规则只需追加 |
| 数据源 | 统一适配层接口 | 日后接土壤传感器/气象站/第三方平台只加适配器 |
| 场景边界 | 问答层识别"超出作用域"并明确拒答 | 日后开新场景时替换作用域定义即可 |

**扩展原则：新方向只加规则和适配器，不动核心引擎。**
