## 二、作品里 AI 具体做什么、不做什么

这是本作品**最重要的设计说明**。

### AI 只做三件事

| 用途 | 说明 |
|---|---|
| **意图识别** | 把用户口语映射到已有分支。例如用户说"啥时候能喷"，规则匹配不到 → 模型判断属于"打药时机" → 输出只是一个类别标签，不产出任何内容 |
| **话术改写** | 把规则引擎的结构化结论改写成农户听得懂的口语 |
| **超范围兜底** | 用户问到能力之外的问题（如病虫害、粮价）时，礼貌说明做不了，不硬答 |

### AI 绝对不做的事

> **不参与任何数值计算。所有温度、风速、日期、时段、降水量，全部来自规则引擎对 Open-Meteo 实时天气数据的计算。**

### 数字一致性校验（可验证的安全机制）

模型改写完成后，程序会抽取输出中的每一个数字，逐个比对原始答案：

- **全部能在原文找到** → 采用
- **出现任何一个新数字** → 立即丢弃，回退到原始模板答案

唯一放行的例外是时间制式转换（`14:00` → "下午2点"），因为这语义完全等价。

这条机制可以在演示时现场验证：关闭"AI 增强"再打开，对比两次回答中的数字是否一致。测试用例中也包含专门断言（见 `web/e2e.mjs` 第 9b 节）。

### 3.3 由 AI 参与、人工决策的关键设计

| 设计决定 | AI 的建议 | 人工判断 |
|---|---|---|
| 首版作物范围 | 收窄到小麦+玉米 | 采纳 |
| 用日最大风速还是逐小时风速判断打药 | 发现日最大风速方案导致所有日期都"不宜"，改为逐小时 | 采纳并测试验证 |

| 大模型接入方式 | 只做意图/改写/兜底，并加数字校验 | 采纳 |
| 地图方案 | 对比 OSM / 高德 / 天地图 / GeoJSON 四种，实测 OSM 在国内不可用 | 采纳"高德 JS API + 本地 GeoJSON 边界" |
| **是否处理坐标偏移** | 发现 GCJ-02 与 WGS-84 相差约 500 米，会致县界误判 | 采纳，加入双向坐标转换算法 |
| 农事阈值数值 | 提供公开常识参考值 | **标注"待核实"，承认未经专业核定** |

## 五、诚信说明

### 1. 天气数据不是 AI 生成的

页面显示的所有温度、降水、风速、日期，全部来自 **Open-Meteo 公开天气 API 的真实返回数据**，每次运行实时拉取。可用浏览器开发者工具 Network 面板直接核验。

### 2. 农事结论不是 AI 自由生成的

农事判断由 `logic.js` 中的**确定性规则**计算得出，大模型只负责"把计算结果写成人话"，且受数字一致性校验约束。

这是出于农业场景严肃性的主动取舍：**农业建议一旦出错会造成真实经济损失，因此每个数字都必须可追溯、可复核。**

### 3. 农事阈值未经专业核定

规则中使用的阈值（打药风速 ≤ 3.4 m/s、气温 5–32℃、7 天降水 < 5 mm 提示灌溉）来自**公开农技常识**，由 AI 提出参考值、团队采纳，**尚未经当地农技部门或指导教师核定**。

界面上每条建议均已标注"阈值待核实"，页面底部固定展示免责声明。团队愿意就阈值依据接受质询。

### 4. 长势趋势为示意数据

"长势趋势"曲线为确定性生成的示意数据，**不代表真实遥感监测结果**，图表下方已明确标注。

## 六、第三方数据与素材

| 内容 | 来源 | 授权/说明 |
|---|---|---|
| 天气数据 | [Open-Meteo](https://open-meteo.com) | 公开免费气象数据，遵守其使用条款 |
| 天气模式 | ECMWF / NOAA-GFS / DWD-ICON / CMA-GRAPES | 通过 Open-Meteo 聚合接口获取，各模式版权归原机构 |
| **地图底图** | **高德地图 JS API** | **通过官方 SDK 调用，使用团队申请的 Web端 key（已授权）**，含审图号显示 |
| 行政区划边界 | [阿里 DataV GeoAtlas](https://datav.aliyun.com/portal/school/atlas/area_selector) | 公开行政区划数据，用于教学演示 |
| 地理编码（兜底） | Open-Meteo Geocoding API | 公开免费接口 |
| 图片素材 | 无 | 界面图标均为内联 SVG 或 Unicode 字符，未使用任何第三方图片 |
| 字体 | 无 | 使用系统默认字体，未嵌入第三方字体文件 |
| 代码库 | 无 | 未引用任何框架、图表库，地图使用高德官方 JS SDK，其余全部原生实现 |

> **关于地图合规**：作品已从"直接请求瓦片 URL"改为**通过高德官方 JS API 调用**，使用团队申请并获批的 Web端 key 与安全密钥。
> 高德 key 为「Web端」类型，仅用于 JS API，不调用 REST 接口。
> 行政区划边界为本地内置的公开数据，通过 WGS-84 → GCJ-02 坐标转换叠加到高德底图上。

## 七、API Key 使用与安全说明

作品前端直接调用两组第三方服务，Key 均以明文形式存放在 `web/config.js` 中：

| 服务 | Key 类型 | 用途 |
|---|---|---|
| DeepSeek | 大模型 API Key | 意图识别、话术改写、超范围兜底 |
| 高德地图 | Web端 Key + 安全密钥 | 地图底图渲染 |

- 已知悉这是**浏览器端调用**，Key 会随页面源码暴露
- 仅用于本地演示与课程作业，**未对外公开发布**
- 若后续需要公开发布，将改为**后端代理转发**，不在前端暴露 Key
- 演示结束后将重置这些 Key
