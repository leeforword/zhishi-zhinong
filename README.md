# 知时智农 · 农事决策助手

面向华北平原**冬小麦 / 夏玉米**种植的农事决策工具。输入地块位置和作物，它回答三件事：

1. **未来 7 天，哪天几点适合打药？**
2. **这几天要不要浇水？**
3. **今天和未来一周有什么农事风险？**

核心不是聊天，而是**把天气预报翻译成可执行的决定**：不说"明天东南风 3 级"，
而说"明天 11 点到 17 点适合打药，风速 1.4 m/s，置信度 96%"。

> 纯静态网页 · 零第三方依赖 · 可安装到手机桌面 · 断网也能打开界面

## 在线使用

部署完成后地址形如：

```
https://leeforword.github.io/zhishi-zhinong/
```

### 装到手机桌面（像 App 一样用）

| 你的手机 | 怎么做 |
|---|---|
| **安卓**（Chrome / Edge） | 打开网址 → 顶栏出现 **↓** 按钮 → 点「安装」；或底栏弹窗里点「安装」 |
| **iPhone / iPad** | **必须用 Safari** 打开 → 底部**分享**按钮 → 往下找 **添加到主屏幕** |
| **微信里打开** | 装不了。点右上角 **···** → **在浏览器打开**，再按上面两种方式装 |

装上之后：有自己的图标、全屏无地址栏、断网时界面仍能打开（会明确提示取不到天气数据）。

### 界面分三个功能区

| | 手机 | 电脑 |
|---|---|---|
| **内容** | 底部 Tab ① | 左侧栏 ① |
| **对话** | 底部 Tab ②（全屏聊天，输入框贴底） | 左侧栏 ② |
| **我的** | 底部 Tab ③ | 左侧栏 ③ |

「内容」是长滚动的一整页（最佳窗口 → 今日判读 → 未来七天 → 五张图表），不拆分。
「我的」包含四块：**地块管理 / 农事阈值 / AI 对话 / 关于**。

> 农事阈值可在「我的」里直接改（风速上限、气温区间、作业时段、降水拦截），
> 改完立刻按新阈值重算。这样当地农技部门有明确标准时，不用改代码。

> ⚠️ 断网只保证**界面**能开。天气数据必须联网取，取不到时会明确告诉你
> "现在没有网络"，**不会**拿上一次的旧数据冒充本次结果——这是农事工具该有的底线。

## 它到底给出什么

| 模块 | 说明 |
|---|---|
| **最佳打药窗口** | 未来 7 天逐小时筛选，给出具体时段、置信度、推迟代价、窗口关闭条件 |
| **集合预报置信度** | 50 个气象成员各算一遍，统计有多少支持这个窗口 |
| **反事实推演** | 点「如果风速收紧到 2.0」等按钮，真的重算一遍，看结论会不会翻转 |
| **今日判读** | 打药 / 灌溉 / 晾晒三种作业分别给结论，并写明依据 |
| **未来七天** | 三个作业维度切换查看，点某天下方图表跟着切换 |
| **多模式一致性** | 同时比对 ECMWF / GFS / ICON / CMA，有分歧就如实说 |
| **问一句** | 自然语言问答（"哪天能打药""要不要浇水"） |
| **数据分析** | 逐小时风速、作业窗口热力图（7×24）、温度降水、可行性环形图、长势趋势 |

所有图表为手写 SVG，没有用任何图表库。

### 一个刻意的设计取舍

**大模型不参与任何数值计算。** 所有数字来自规则引擎对真实天气数据的计算，
大模型只做三件事：意图识别、话术润色、超范围兜底。改写结果还要过一道
**数字一致性校验**：输出里出现的每个数字都必须在原始答案中出现过，否则整段丢弃、
回退模板。

所以关掉大模型之后，结论和数字**完全不变**，只是措辞更朴素。

### AI 对话怎么开（可选，走中转）

网站是纯静态的，源码全网可见，所以**不能把 API key 写进前端**。正确做法是加一层
Cloudflare Worker 中转：

```
浏览器 ──POST──▶ Worker（key 在服务端）──▶ DeepSeek
   ↑ 没有 key              ↑ 有 key
```

部署步骤见 **[worker/README.md](worker/README.md)**（全程免费，约 10 分钟）。
部署完把 Worker 地址填进 **我的 → AI 对话 → 中转地址**，或者写进 `web/config.js`
的 `llmProxyUrl`。

不配也能用：问答会退回「纯规则引擎模式」，界面会明确显示当前是哪一种。

## 本地运行

不需要安装任何依赖，Node 只用来起静态服务器。

```bash
# 方式一：起本地服务（推荐，"用我的位置" 功能需要它）
cd web
node server.mjs 8931
# 浏览器打开 http://127.0.0.1:8931

# 方式二：直接双击 web/index.html
# 也能用，但浏览器禁止 file:// 页面调用定位
```

### 想在本机打开 AI 润色

公开配置里 `deepseekKey` 是空的。要开，新建 `web/config.local.js`：

```js
Object.assign(window.TIANZHI_CONFIG, {
  deepseekKey: '你的 key',
  enableLLM: true
});
```

这个文件已被 `.gitignore` 忽略，**不会**上传，构建脚本也不复制它。

## 构建与部署

```bash
node scripts/build-site.mjs    # web/ → site/（发布用的成品）
node scripts/test-pwa.mjs      # 真浏览器验证：能装、能离线、图标齐全

# 直接测线上（真实 HTTPS + 真实子路径，比本地测更严格）
node scripts/test-pwa.mjs --url=https://leeforword.github.io/zhishi-zhinong/
```

推送到 `main` 分支后，GitHub Actions 会自动构建并发布到 Pages。
详细的手把手步骤见 **[docs/部署与安装.md](docs/部署与安装.md)**。

构建脚本自带自检，任一条不过就直接失败：

- 产物里不能出现任何 DeepSeek key
- `manifest.webmanifest` 必须是合法 JSON，且含 512×512 与 maskable 图标
- `index.html` 引用的每个本地文件都必须存在
- **Service Worker 的预缓存清单必须和磁盘上的文件一一对应**（对不上就会出现
  "装到手机上、一断网就白屏"，而这种问题在电脑上永远发现不了）

## 数据来源

| 内容 | 来源 | 说明 |
|---|---|---|
| **实时天气（主预报）** | **和风天气** | `/v7/weather/168h` 168 小时逐时 + 7 天逐日，同化国内站网，带逐时降水概率 `pop` |
| 分钟级降水 / 灾害预警 | 和风天气 | 未来 2 小时每 5 分钟 |
| 集合预报（置信度） | Open-Meteo Ensemble | 50 个成员，用于算"这个窗口有多稳" |
| 多模式分歧 | Open-Meteo（ECMWF / GFS / ICON / CMA） | 用来如实暴露不确定性；主源故障时也由它兜底 |
| 地图底图 | 高德地图 JS API | 路网 / 卫星可切换 |
| **地名到村** | 高德逆地理编码 + BigDataCloud | 高德给到村/乡镇，BigDataCloud 兜底到乡镇；都拿不到才退回本地县界 |
| 行政区划边界 | 阿里 DataV GeoAtlas | 河北省 + 11 地级市 + 167 个县级单元，离线内置 |
| 点位反查县名 | 本地 GeoJSON 点面判断 | 离线，不依赖在线服务 |

为什么主预报用和风而不是 Open-Meteo：和风同化了国内地面观测站，县域尺度的温度和风更贴本地，
而且逐时数据带降水概率。但和风的免费额度**给不了**集合预报和多模式分歧，
而这两样正是本作品"置信度"和"分歧提示"的依据——所以它们仍走 Open-Meteo，
两者分工而不是互相替代。

坐标系做了双向转换：高德用 **GCJ-02**，天气与行政边界用 **WGS-84**，
两者在华北相差约 500 米——不转换的话，县界附近会判断错县，村名也会偏到隔壁村。

## 已知限制（如实说明）

| 限制 | 说明 |
|---|---|
| **村名不保证每块地都能识别** | 行政村名字靠地图服务商的 POI/AOI 数据，不是官方行政区划库。识别不到时界面会如实退到"乡镇/街道"，不会拿乡镇名冒充村名 |
| **高德逆地理编码需要正确的安全密钥** | 安全密钥（`amapSecurityJsCode`）配错时所有"服务类"接口返回 `INVALID_USER_SCODE`，地图还能显示但取不到村名。控制台重新复制一次即可 |
| **域名白名单会挡住本地预览** | 白名单里没有 `localhost` 时，本机打开地图会失败（线上正常）。本地开发需要把 `localhost` 也加进去 |
| 农事阈值未经核定 | 风速、气温等来自公开农技常识，**未**经当地农技部门核定，界面已标注"待核实" |
| 天气预报本身有不确定性 | 不同模式结论可能相反，作品的做法是如实暴露分歧，而不是假装单点预报可靠 |
| 天气网格约 9–11 km | 代表县域范围，不是单个地块 |
| 长势趋势为示意数据 | 真实遥感未接入，曲线仅演示形态，界面已明确标注 |
| 无作物生育期模型 | 目前只区分冬小麦 / 夏玉米，没有越冬期、拔节期等阶段差异 |
| 打药未考虑风向与药后降雨 | 目前只看风速与当日降水 |
| 病虫害识别、测土施肥未做 | 问答中会明确拒答，不编造 |

**本工具输出的一切建议仅供参考。** 农事操作受土壤、品种、苗情、历史管理等多重因素影响，
实际决策请以当地农技部门指导意见和农药标签说明为准。

## 配置与安全

仓库是公开的，所以三把 key 的处理方式不同：

| key | 是否入库 | 理由 |
|---|---|---|
| 高德地图 `amapKey` | ✅ 保留 | 有域名白名单机制，**请务必在控制台绑定你的托管域名**，绑定后别的站用不了 |
| 和风天气 `qweatherKey` | ✅ 保留 | 免费额度，被刷爆只是当天数据不全，控制台可随时换 |
| DeepSeek `deepseekKey` | ❌ **不入库** | 按量计费，泄露等于直接扣钱。**放在 Cloudflare Worker 的环境变量里**（见 [worker/README.md](worker/README.md)），前端只知道中转地址 |
| Cloudflare Worker 地址 | ✅ 入库 | 地址本身不含密钥，公开无风险 |
